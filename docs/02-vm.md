# 2. The VM

## What you need

* A **Windows 11 IoT Enterprise LTSC 2024** ISO (build 26100). Not included; get it from Microsoft (evaluation or volume licence). This is what the setup was built and measured on.
  Other Windows 11 editions are likely fine for the 3D part but are untested here.
* `virtio-win.iso`: <https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/stable-virtio/virtio-win.iso>

## Create it

```bash
sudo bash scripts/create-vm.sh --windows-iso ~/Downloads/win11-ltsc.iso --virtio-iso ~/Downloads/virtio-win.iso
#   options: --name win11 --vcpus 8 --memory-gib 8 --disk-gib 160 --rendernode /dev/dri/renderD128
#   check first without root: add --dry-run (prints the final XML)
```

The script runs `virt-install --dry-run --print-xml` for a normal Windows 11 guest, rewrites the XML with [`scripts/apply-3d.py`](../scripts/apply-3d.py) and defines it.
To convert an **existing** Windows VM instead, shut it down and run:

```bash
virsh -c qemu:///system dumpxml --inactive win11 | python3 scripts/apply-3d.py > win11-3d.xml
virsh -c qemu:///system define win11-3d.xml
```

## What the XML contains

| Setting | Value | Reason |
|---|---|---|
| CPU/memory | host-passthrough, 8 vCPU, 8 GiB, memfd shared | author's choice; adjust freely |
| Firmware | UEFI, Secure Boot code, **no enrolled keys**; TPM 2.0 (swtpm, CRB) | Windows 11 wants TPM + UEFI; test-signed driver needs Secure Boot not enforced |
| Disk | virtio qcow2, `cache=writeback`, `discard=unmap` | see docs/01 (btrfs) |
| Video | `virtio` with `<acceleration accel3d='yes'/>` | 3D virtio-gpu |
| QEMU args | `-global virtio-vga-gl.blob=true`, `.hostmem=4G`, `.venus=true` | Venus; 4 GiB BAR through which the guest maps host GPU memory |
| Graphics | SPICE on `/var/lib/libvirt/qemu/win11-spice.sock`, GL on the render node | local dma-buf scanout, fixed path so the second `-spice` matches |
| QEMU args | second `-spice … max-refresh-rate=120` | QEMU uses the **last** `-spice`; default rate is 30 |
| QEMU env | `QEMU_MODULE_DIR=/tmp/qemu-modules-1ms` | the fence-poll patch, [docs/04](04-speedups.md); if the directory is missing QEMU falls back to the stock modules |
| Guest agent channel | `org.qemu.guest_agent.0` | used by the launcher and by `scripts/guest-ps.py` |

## Install Windows

1. `virsh -c qemu:///system start win11` and `virt-viewer -c qemu:///system --attach win11`.
2. In Windows setup the disk is empty because it is **virtio**: click *Load driver* → browse the **virtio-win** CD → `viostor\w11\amd64`. (Network: `NetKVM\w11\amd64`; the guest tools below also install it.)
3. Windows 11 setup checks TPM/Secure Boot *capability*; the emulated TPM 2.0 and the Secure Boot-capable firmware satisfy it even without enrolled keys. If your installer still refuses,
   the usual registry bypass (`LabConfig`) works on IoT LTSC too. This path was not re-run by the author for this repo, see the status note in the README.
4. After the first login, run `virtio-win-guest-tools.exe` from the virtio-win CD: it installs the remaining virtio drivers, the **QEMU guest agent** and the SPICE tools.
   Check from the host: `virsh -c qemu:///system qemu-agent-command win11 '{"execute":"guest-ping"}'` must print `{"return":{}}`.
5. Shut Windows down completely and start it again. Continue with [docs/03-guest.md](03-guest.md).

## Back up before the driver step

```bash
sudo bash scripts/export-vm.sh ~/vm-backups/win11-pre-3d      # shuts the VM down cleanly first
```
[`scripts/export-vm.sh`](../scripts/export-vm.sh) saves the definition, the UEFI variables + TPM state (a tar) and the disk (`qemu-img convert`, with `SHA256SUMS`).
